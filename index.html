Flutter Release PipelineIntroduction  ·  01
The problem

Every release was done by hand

One developer, on one laptop, repeating the same steps for every build — and he was the only person who knew all of them.

01

Everything was manual

Take the code, place the environment and secret files, run the build, wait, then upload the artifact and retype the version.

02

Mistakes surfaced last

A wrong environment, a mismatched Flutter version or a used build number only appeared after a forty-minute build.

03

The release was slow

Half a day per release. The testing team waited, the client waited, and the developer watched a build screen.

04

Uploading was its own job

Play Console and TestFlight, by hand, two logins and two sets of keys. Forget it and a finished build waits.

Flutter Release PipelineThe problem  ·  02
The solution

Five steps, the same order, every time

01

Clone the repository

Clones the branch from GitLab with a stored credential and prints the exact commit.

02

Bring the secret files

Environment values from Infisical, keystore and store keys from object storage.

03

Generate the code

Generated Dart files are git-ignored, so they are rebuilt after the environment file.

04

Build the release

Flutter for a normal build, Shorebird for a code push, on the exact pinned SDK.

05

Upload it automatically

fastlane to Play internal testing, altool to TestFlight. Nothing goes up by hand.

The clone URL

Host and path are kept apart so the URL is assembled in one place, and the protocol decides its shape.

ssh  git@HOST:PATH.git

https  https://HOST/PATH.git

SSH needs port 22 open, so HTTPS is used from outside the office network. The credential kind has to match.

Flutter
Always
FLUTTER_VERSION3.44.6

FVM installs this exact SDK on the agent and the build fails if the active version does not match, so the same commit produces the same build on any machine.

Flutter Release PipelineSource & SDK  ·  05
Group 3 & 4

Where the secrets come from

Infisical
Always
INFISICAL_API_URLapp.infisical.com
INFISICAL_PROJECT_IDebac93cc-…
INFISICAL_ENVprod
INFISICAL_TOKEN_CREDENTIALS_IDinfisical-token

Exported to .env in the project root.

Object storage
With files
S3_ENDPOINT…r2.cloudflarestorage.com
S3_REGIONauto
S3_CREDENTIALS_IDr2-credentials

Any S3-compatible service works — R2, MinIO, B2, Spaces. Only the endpoint changes.

Secret files
Per file

One line per file. The key is where it lands in the project, the value is where it comes from.

SECRET_FILE.<path>=s3://<bucket>/<object>

Keystore, google-services.json, the iOS plist, the Play service account and the Apple key all travel this way. A project with no such line skips the download.

iOS
ASC_KEY_ID7UB3848ZB4

Apple authenticates with all three. The issuer id cannot be read off the key file.

Shorebird
Code push
SHOREBIRD_TOKEN_CREDENTIALS_IDshorebird-token

Only read when the build runner is Shorebird. The token is proved non-empty in the first stage, so a bad one fails in seconds instead of after the whole build.
