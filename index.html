⚠️The problem

How a release used to happen, what went wrong every time, and what it cost the team.

The problem

Every release was done by hand

One developer, on one laptop, repeating the same steps for every build — and he was the only person who knew all of them.

01

✋Everything was manual

Take the code, place the environment and secret files, run the build, wait, then upload the artifact and retype the version.

02

⏱️Mistakes surfaced last

A wrong environment, a mismatched Flutter version or a used build number only appeared after a forty-minute build.

03

🐌The release was slow

Half a day per release. The testing team waited, the client waited, and the developer watched a build screen.

04

📤Uploading was its own job

Play Console and TestFlight, by hand, two logins and two sets of keys. Forget it and a finished build waits.

⚙️The solution

The five stages the pipeline runs, in the same order, on every build.

The solution

Five steps, the same order, every time

01

📥Clone the repository

Clones the branch from GitLab with a stored credential and prints the exact commit.

02

🔐Bring the secret files

Environment values from Infisical, keystore and store keys from object storage.

03

🧬Generate the code

Generated Dart files are git-ignored, so they are rebuilt after the environment file.

04

🏗️Build the release

Flutter for a normal build, Shorebird for a code push, on the exact pinned SDK.

05

🚀Upload it automatically

fastlane to Play internal testing, altool to TestFlight. Nothing goes up by hand.

🔗The clone URL

Host and path are kept apart so the URL is assembled in one place, and the protocol decides its shape.

ssh  git@HOST:PATH.git

https  https://HOST/PATH.git

SSH needs port 22 open, so HTTPS is used from outside the office network. The credential kind has to match.

🐦Flutter
Always
FLUTTER_VERSION3.44.6

FVM installs this exact SDK on the agent and the build fails if the active version does not match, so the same commit produces the same build on any machine.

🪣Object storage
With files
S3_ENDPOINT…r2.cloudflarestorage.com
S3_REGIONauto
S3_CREDENTIALS_IDr2-credentials

Any S3-compatible service works — R2, MinIO, B2, Spaces. Only the endpoint changes.

📄Secret files
Per file

One line per file. The key is where it lands in the project, the value is where it comes from.

SECRET_FILE.<path>=s3://<bucket>/<object>

Keystore, google-services.json, the iOS plist, the Play service account and the Apple key all travel this way. A project with no such line skips the download.

🧰Getting set up

What a developer does once, before the pipeline can ship their app. Two store accounts, two keys, and one handover to DevOps.

XcodeApp Store Connect Google CloudPlay Console
Apple

Three steps for iOS

💻Runner Mac
Step 01

🔓Sign in to Xcode

Settings → Accounts → add the Apple account and pick the team. Certificates and provisioning profiles then install themselves.

It has to be the runner Mac. Signing in on your own laptop does nothing for the pipeline.

🍎App Store Connect
Step 02

🔑Create an API key

Users and Access → Integrations → App Store Connect API. Set the role to App Manager — the smallest role that can upload builds and manage versions.

Note the Issuer ID and Key ID. The .p8 downloads exactly once and cannot be recovered.

📝Text editor
Step 03

📄Write ExportOptions.plist

Copy the template and replace teamID with your Apple Developer Team ID.

Leave method as app-store-connect. Any other value signs the app for something else and TestFlight rejects the build.

Flutter Release PipelineApple setup  ·  08
Google

Four steps for Android

☁️Cloud Console
Step 01

🔌Enable the API

APIs & Services → Library → Google Play Android Developer API → Enable.

Without it the key authenticates fine but every upload fails.

☁️Cloud Console
Step 02

👤Create the account

IAM & Admin → Service Accounts → create play-store-ci.

Leave every Google Cloud role empty. Access is granted in the Play Console, not here.

☁️Cloud Console
Step 03

🗝️Create a JSON key

Open the account → Keys → Add key → Create new key → JSON.

Google never shows it again. Lose the file and you make a new key.

▶️Play Console
Step 04

✅Grant access

Users and permissions → invite the client_email from the JSON, not your own.

Tick Release apps to testing tracks and View app information. Owner or admin only.

Handover

What to give DevOps

🍎Apple
All four
AuthKey_<KeyID>.p8secret
Key IDidentifier
Issuer IDidentifier
ExportOptions.plistsettings

The key alone is not enough — every Apple API call is signed with all three, and the issuer id lives only on that page.

🤖Google
Both
service-account.jsonsecret
client_emailidentifier

The email is what gets invited to the Play Console. Without that grant the key exists but can do nothing.

🔒How to send them

🔒Secrets go through a vault

A password manager or a secrets vault — never email, Slack, or a git commit. The .p8 signs your App Store identity and the JSON can publish to your listing.

The identifiers and the plist are just settings, so those are fine to paste anywhere.
