Ship iOS Builds Without Logging Into Xcode On The Build Machine.

Everything you must do, in order, on two computers. The Development Mac collects the signing files one time. The Pipeline Mac builds the app forever after, with no Apple account on it at all.

30 min · Development Mac, once ever 45 min · Pipeline Mac, once ever 5 min · per new project 1×/year · manual work after that
Section 01

What we are building, in plain words

One Jenkins job. You pick Android or iOS, type the version and the build number, press Build. The job gets the code, gets the secret files, builds the app, and sends it to the store. Nobody types an Apple password anywhere.

The two Macs

Machine 1

Development Mac — the one you work on

It has Xcode open, a keychain holding your certificates, and a human at the keyboard. You use it once, to collect the signing files. After that it plays no part in a build.

Machine 2

Pipeline Mac — the one that builds

It runs the Jenkins agent. Xcode is installed but never signed in. Every build brings its own certificate and profile, uses them, then deletes them.

Who does what

TaskDevelopment MacPipeline Mac
Create the App Store Connect API keyYes — in a browser, once everNo
Export the distribution certificate (.p12)Yes — only this Mac holds the private keyNo
Create the provisioning profile in Apple's portalYes — once per appNo
Upload the secrets to storageYesNo

Run the Jenkins agentNoYes
Sign in to Xcode with an Apple IDFine, you already areNever
Build the appNoYes, every time

The five things iOS signing needs

Logging into Xcode hands you all five by hand. Each one gets a replacement a script can use.

ThingWhere it comes fromHow often you touch it
dist.p12Exported from the Development Mac keychainOnce a year — it expires
p12 passwordYou choose it during the exportOnce a year
AuthKey.p8App Store Connect → API keyOnce ever
Key ID + Issuer IDSame page as the .p8Once ever
Provisioning profileDownloaded from Apple every buildNever again

The whole ideaThe profile is the part that expires fastest, so the build downloads a fresh one every time and you stop thinking about it. The certificate cannot be re-made per build — Apple allows only two or three per account — so it is stored once and treated like a password.

Order of work

  • Section 02 — Development Mac. Collect the signing files. 30 minutes, once ever.
  • Section 03 — Pipeline Mac. Install the tools and the Jenkins agent. 45 minutes, once ever.
  • Section 04 — Jenkins. Credentials, node, job. 15 minutes.
  • Section 05 — Add two scripts and a few settings to this repository.
  • Sections 06–07 — Run it by hand first, then from Jenkins, then turn on the upload.
Section 02

Development Mac — collect the signing files

Machine 1 Once ever About 30 minutes

Do all of this on the Mac where you normally open Xcode. Every future project reuses the same files, so this is the last time.

01

Check if a distribution certificate already exists

Terminal · Development Mac

This lists the signing identities sitting in your keychain.

Terminal
security find-identity -v -p codesigning | grep "Apple Distribution"

If you see Apple Distribution: Your Company (TEAMID), go to step 2.

If nothing prints, a teammate has it, or nobody has made one. Ask first. If truly nobody has one: Xcode → Settings → Accounts → pick the team → Manage Certificates → + → Apple Distribution.

CarefulApple allows only two or three distribution certificates for the whole account. Do not create a new one just because you cannot find the old one — you can lock the team out. Ask for a teammate's .p12 instead.

02

Create an App Store Connect API key

Browser · appstoreconnect.apple.com

Go to Users and Access → Integrations → App Store Connect API and press +. Name it CI Pipeline and set the role to App Manager.

Which role?The Access box offers Admin, App Manager, Developer, Finance, Sales and Reports, Customer Support and Marketing. Pick App Manager — it is the smallest role that can upload builds and manage App Store versions. Admin works too but hands CI far more than it needs, and Developer cannot manage versions, so the upload step fails.

Write down three things from that page:

  • Issuer ID — the long id at the top, like 69a6de7e-1234-4c5b-8f21-9a0bcdef1234
  • Key ID — the short id in the row, like 2X9R4HXF34
  • The .p8 file — press Download

One chance onlyThe .p8 downloads exactly once. Lose it and you must revoke the key and start again. Save it somewhere safe before you close the page.

03

Export the certificate as a .p12 file

Keychain Access app · Development Mac

This is the last time you use a window with buttons for signing.

  • Open Keychain Access
  • Click My Certificates in the sidebar
  • Find Apple Distribution: Your Company (TEAMID)
  • Click the small arrow beside it — a private key must appear underneath. No key means this Mac cannot export it
  • Right click → Export
  • Format: Personal Information Exchange (.p12)
  • Save as dist.p12 and set a password

Write that password down. It goes into Jenkins in step 7.

04

Create the provisioning profile in Apple's portal

Browser · developer.apple.com

  • Certificates, Identifiers & Profiles → Profiles
  • Press +
  • Choose App Store Connect under Distribution
  • Pick the App ID — the bundle id of your app
  • Pick the certificate from step 3
  • Name it clearly, for example CM App AppStore, and generate it

Do not download itThe profile only needs to exist. From now on the build pulls it from Apple every single time, so it can never go stale on you.

05

Find the bundle id and the Team ID

Terminal · inside the Flutter app repository

Terminal
grep -r PRODUCT_BUNDLE_IDENTIFIER ios/Runner.xcodeproj/project.pbxproj | sort -u

The Team ID is the ten character code on developer.apple.com → Membership. It is also the code inside the brackets of your certificate name.

06

Put the two files into the S3 / R2 bucket

Terminal · Development Mac

This repository already downloads secret files from object storage — the keystore, the plists. The .p8 and the .p12 are the same kind of thing, so they go to the same place. No base64, no new plumbing.

Terminal
export AWS_ACCESS_KEY_ID="your access key id"
export AWS_SECRET_ACCESS_KEY="your secret access key"
export AWS_DEFAULT_REGION=auto
ENDPOINT=https://<account-id>.r2.cloudflarestorage.com

aws s3 cp AuthKey_2X9R4HXF34.p8 s3://com-chinmayamission-app/AuthKey.p8 --endpoint-url "$ENDPOINT"
aws s3 cp dist.p12              s3://com-chinmayamission-app/dist.p12   --endpoint-url "$ENDPOINT"

Use the same bucket and endpoint that are already written in pipeline.properties.

07

Add the p12 password to Jenkins

Browser · your Jenkins

Manage Jenkins → Credentials → add a Secret text credential with ID ios-p12-password and the password from step 3 as its value.

That is the only new credential needed. The Key ID and the Issuer ID are identifiers, not passwords — they go into pipeline.properties, see section 05.

08

Clean up, and set one calendar reminder

Terminal · Development Mac

Terminal
rm -P dist.p12 AuthKey_2X9R4HXF34.p8

Then put one entry in the calendar, eleven months from today: "re-export dist.p12 and upload it again". That is the only manual work left, forever.

Section 03

Pipeline Mac — set up the build machine

Machine 2 Once ever About 45 minutes

From a fresh Mac to a working Jenkins agent. Do these in order. Nothing here involves an Apple account.

01

Make a real user account and log in on the screen

Create a normal user, for example builder. Log in at the physical screen at least once, not only over SSH. macOS keychains behave differently without a real login session, and that is the number one cause of builds that work in a terminal but fail in Jenkins.

Turn on automatic login — System Settings → Users & Groups → Automatically log in as builder — then stop the machine sleeping.

Terminal · Pipeline Mac
sudo pmset -a sleep 0 displaysleep 0 disksleep 0
sudo systemsetup -setremotelogin on          # so you can SSH in later
02

Install Xcode and accept the licence

Install Xcode from the App Store. Open it once so it finishes installing its components, then close it and run these.

Terminal · Pipeline Mac
sudo xcode-select -s /Applications/Xcode.app/Contents/Developer
sudo xcodebuild -license accept
sudo xcodebuild -runFirstLaunch
xcodebuild -version

Do not sign inWhen Xcode asks for an Apple ID, close the window. This Mac must never hold an Apple account. Every build brings its own certificate and deletes it afterwards.

Terminal · Pipeline Mac
launchctl load -w ~/Library/LaunchAgents/com.jenkins.agent.plist
launchctl list | grep jenkins
tail -f ~/jenkins-agent/logs/agent.out.log

The most common mistake of allThe file belongs in ~/Library/LaunchAgents — a LaunchAgent, which runs as you. Never in /Library/LaunchDaemons. A daemon has no user session and signing fails in ways that are very hard to read. The PATH must also include /opt/homebrew/bin, or the build cannot find brew, fvm or pod.

09

Open the network

The Pipeline Mac must reach these on port 443:

  • api.appstoreconnect.apple.com — the profile is downloaded every build
  • *.r2.cloudflarestorage.com — or whatever your S3 endpoint is
  • app.infisical.com — for the .env file
  • gitlab.webelight.co.in — the code
  • Apple's upload servers — for TestFlight

Cloning over SSH also needs port 22 to GitLab. Inside the office that is usually open, outside it usually is not — which is why GIT_PROTOCOL=https is the safer default.

Section 04

Jenkins — credentials, node, job

The Jenkinsfile never holds a secret. It holds the name of a secret, and Jenkins hands the value over at build time.

Credentials to create

Manage Jenkins → Credentials → System → Global → Add Credentials. The ID on the left must match exactly what is written in pipeline.properties.

Credential IDKindWhat goes inside
gitlab-tokenUsername with passwordUsername oauth2, password is the GitLab access token
infisical-tokenSecret textThe Infisical service token
shorebird-tokenSecret textThe Shorebird CI token
r2-credentialsUsername with passwordUsername is the Access Key ID, password is the Secret Access Key
ios-p12-passwordSecret textThe password you set when exporting dist.p12

If you switch to SSHWith GIT_PROTOCOL=ssh the gitlab-token credential must instead be an SSH Username with private key, username git. The kind must always match the protocol.

The node

One node, label macos, created in section 03. The Jenkinsfile opens with agent { label 'macos' }, so a wrong label means the job waits forever and never prints an error.

The job

  • New Item → Pipeline → name it, for example flutter-release-pipeline
  • Pipeline → Definition: Pipeline script from SCM
  • SCM: Git → this repository → credentials → branch main
  • Script Path: Jenkinsfile
  • Save and run once — that first run registers the parameters

After that run the build page shows the four parameters the Jenkinsfile declares: PLATFORM, BUILD_RUNNER, BUILD_VERSION and APP_BUILD_NUMBER.

Add one more parameter

Very useful while testing — build the IPA but do not upload it.

Jenkinsfile · parameters block
booleanParam(
    name: 'DO_UPLOAD',
    defaultValue: false,
    description: 'Send the build to TestFlight. Leave off to only produce the IPA.'

2 · ci/fetch_profile.py

Asks Apple for the provisioning profile and writes it into both folders Xcode looks in — Xcode 16 moved the location and older versions still read the old one. Uses only Python and openssl, both already on the Mac.

ci/fetch_profile.py
#!/usr/bin/env python3
"""
Downloads the provisioning profile for one bundle id from the
App Store Connect API. No third-party packages: stdlib + openssl only.

Reads from environment:
  ASC_KEY_ID        Key ID from App Store Connect
  ASC_ISSUER_ID     Issuer ID from App Store Connect
  P8_PATH           Path to the AuthKey_XXXX.p8 file
  APP_IDENTIFIER    Bundle id, e.g. com.acme.app
  PROFILE_TYPE      IOS_APP_STORE or IOS_APP_ADHOC
  OUT_DIRS          JSON list of folders to write the profile into
  ENV_OUT           Path to write PROFILE_NAME / PROFILE_UUID / PROFILE_FILE
"""
import base64
import json
import os
import subprocess
import sys
import time
import urllib.error
import urllib.request

API = "https://api.appstoreconnect.apple.com"


def need(name):
    v = os.environ.get(name)
    if not v:
        sys.exit("fetch_profile: missing environment variable " + name)
    return v


KEY_ID = need("ASC_KEY_ID")
ISSUER = need("ASC_ISSUER_ID")
P8 = need("P8_PATH")
BUNDLE = need("APP_IDENTIFIER")
PTYPE = os.environ.get("PROFILE_TYPE", "IOS_APP_STORE")
OUT_DIRS = json.loads(need("OUT_DIRS"))
ENV_OUT = need("ENV_OUT")


def b64url(raw):
    return base64.urlsafe_b64encode(raw).rstrip(b"=")


def der_to_raw(der):
    """openssl signs ES256 as DER. Apple wants raw r||s, 64 bytes."""
    if der[0] != 0x30:
        sys.exit("fetch_profile: unexpected signature format from openssl")
    idx = 2 + ((der[1] & 0x7F) if der[1] & 0x80 else 0)
    out = b""
    for _ in range(2):
        if der[idx] != 0x02:
            sys.exit("fetch_profile: unexpected signature format from openssl")
        length = der[idx + 1]
        value = der[idx + 2:idx + 2 + length].lstrip(b"\x00")
        out += value.rjust(32, b"\x00")
        idx += 2 + length
    return out


def make_token():
    now = int(time.time())
    header = {"alg": "ES256", "kid": KEY_ID, "typ": "JWT"}
    payload = {"iss": ISSUER, "iat": now, "exp": now + 900,
               "aud": "appstoreconnect-v1"}
    signing_input = (
        b64url(json.dumps(header, separators=(",", ":")).encode())
        + b"."
        + b64url(json.dumps(payload, separators=(",", ":")).encode())
    )
    result = subprocess.run(
        ["openssl", "dgst", "-sha256", "-sign", P8, "-binary"],
        input=signing_input, capture_output=True,
    )
    if result.returncode != 0:
        sys.exit("fetch_profile: openssl could not sign. Is the .p8 valid?\n"
                 + result.stderr.decode()[:400])
    return (signing_input + b"." + b64url(der_to_raw(result.stdout))).decode()


def api_get(path, token):
    request = urllib.request.Request(
        API + path, headers={"Authorization": "Bearer " + token})
    try:
        with urllib.request.urlopen(request, timeout=60) as response:
            return json.load(response)
    except urllib.error.HTTPError as error:
        sys.exit("fetch_profile: API call failed (%s)\n%s"
                 % (error.code, error.read().decode()[:500]))
    except urllib.error.URLError as error:
        sys.exit("fetch_profile: network error: %s" % error.reason)


token = make_token()
data = api_get(
    "/v1/profiles?include=bundleId&limit=200"
    "&fields[profiles]=name,uuid,profileType,profileState,profileContent",
    token,
)

bundle_names = {
    item["id"]: item["attributes"]["identifier"]
    for item in data.get("included", [])
    if item["type"] == "bundleIds"
}

chosen = None
for profile in data.get("data", []):
    attrs = profile["attributes"]
    rel = profile.get("relationships", {}).get("bundleId", {}).get("data") or {}
    if (attrs.get("profileType") == PTYPE
            and attrs.get("profileState") == "ACTIVE"
            and bundle_names.get(rel.get("id")) == BUNDLE):
        chosen = attrs
        break

if not chosen:
    sys.exit("fetch_profile: no ACTIVE %s profile found for %s.\n"
             "Create it once by hand at developer.apple.com > Profiles, then re-run."
             % (PTYPE, BUNDLE))

blob = base64.b64decode(chosen["profileContent"])
filename = "ci_%s.mobileprovision" % chosen["uuid"]
for folder in OUT_DIRS:
    os.makedirs(folder, exist_ok=True)
    with open(os.path.join(folder, filename), "wb") as handle:
        handle.write(blob)

with open(ENV_OUT, "w") as handle:
    handle.write("PROFILE_NAME=%s\n" % json.dumps(chosen["name"]))
    handle.write("PROFILE_UUID=%s\n" % json.dumps(chosen["uuid"]))
    handle.write("PROFILE_FILE=%s\n" % json.dumps(filename))

print("fetch_profile: using '%s' (%s)" % (chosen["name"], chosen["uuid"]))

3 · ci/ios_build.sh

The whole iOS build: six steps, then a cleanup that always runs. Three things here differ from a generic script — it uses fvm flutter so the pinned SDK is used, it takes the .p12 and .p8 as files because the pipeline already downloads them, and it builds inside APP_DIR because the app lives in the Jenkins workspace while the script lives in this repo.

ci/ios_build.sh
#!/usr/bin/env bash
# ---------------------------------------------------------------------------
# ios_build.sh - build a Flutter iOS app and send it to TestFlight.
# No Apple ID login on this machine.
# Uses only: security, xcodebuild, xcrun, python3, openssl, fvm flutter, pod.
# ---------------------------------------------------------------------------
set -euo pipefail

# ------------------------------ inputs -------------------------------------
APP_DIR="${APP_DIR:?set APP_DIR: the folder that holds pubspec.yaml}"
APP_IDENTIFIER="${APP_IDENTIFIER:?set APP_IDENTIFIER, e.g. com.acme.app}"
TEAM_ID="${TEAM_ID:?set TEAM_ID, e.g. ABCDE12345}"
SCHEME="${SCHEME:-Runner}"
XCODE_CONFIG="${XCODE_CONFIG:-Release}"
FLUTTER_FLAVOR="${FLUTTER_FLAVOR:-}"
PROFILE_TYPE="${PROFILE_TYPE:-IOS_APP_STORE}"
EXPORT_METHOD="${EXPORT_METHOD:-app-store-connect}"   # Xcode 15 or older: app-store
BUILD_NAME="${BUILD_NAME:?set BUILD_NAME, e.g. 1.0.0}"
BUILD_NUMBER="${BUILD_NUMBER:?set BUILD_NUMBER, e.g. 32}"
DO_UPLOAD="${DO_UPLOAD:-false}"
FLUTTER="${FLUTTER:-fvm flutter}"

# ------------------------------ secrets ------------------------------------
ASC_KEY_ID="${ASC_KEY_ID:?missing ASC_KEY_ID}"
ASC_ISSUER_ID="${ASC_ISSUER_ID:?missing ASC_ISSUER_ID}"
P8_PATH="${P8_PATH:?missing P8_PATH, the AuthKey.p8 file}"
P12_PATH="${P12_PATH:?missing P12_PATH, the dist.p12 file}"
IOS_P12_PASSWORD="${IOS_P12_PASSWORD:?missing IOS_P12_PASSWORD}"

# ------------------------------- paths -------------------------------------
CI_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
cd "$APP_DIR"
WORK="$APP_DIR/build/ci"
ARCHIVE="$WORK/$SCHEME.xcarchive"
IPA_DIR="$WORK/ipa"
KEYCHAIN="$HOME/Library/Keychains/ci-signing-$$.keychain-db"
KEYCHAIN_PW="$(openssl rand -base64 24)"
LOGIN_KEYCHAIN="$HOME/Library/Keychains/login.keychain-db"
PROFILE_DIR_NEW="$HOME/Library/Developer/Xcode/UserData/Provisioning Profiles"
PROFILE_DIR_OLD="$HOME/Library/MobileDevice/Provisioning Profiles"
export LC_ALL=en_US.UTF-8 LANG=en_US.UTF-8

rm -rf "$WORK"; mkdir -p "$WORK" "$IPA_DIR"
step() { printf '\n=== %s\n' "$1"; }

# --------------------------- always clean up -------------------------------
# This Mac is not thrown away after the build, unlike a cloud runner.
# Without this, keychains and profiles pile up and one day sign the wrong app.
INSTALLED_PROFILE=""
cleanup() {
  set +e
  step "cleanup"
  security list-keychains -d user -s "$LOGIN_KEYCHAIN" >/dev/null 2>&1
  security delete-keychain "$KEYCHAIN" >/dev/null 2>&1
  if [ -n "$INSTALLED_PROFILE" ]; then
    rm -f "$PROFILE_DIR_NEW/$INSTALLED_PROFILE" "$PROFILE_DIR_OLD/$INSTALLED_PROFILE"
  fi
  rm -f "$P12_PATH" "$P8_PATH"
  rm -f "$HOME/.appstoreconnect/private_keys/AuthKey_$ASC_KEY_ID.p8"
}
trap cleanup EXIT

# ========================= 1. certificate ==================================
step "1/6 installing the certificate into a throwaway keychain"
security create-keychain -p "$KEYCHAIN_PW" "$KEYCHAIN"
security set-keychain-settings -lut 21600 "$KEYCHAIN"
security unlock-keychain -p "$KEYCHAIN_PW" "$KEYCHAIN"
security import "$P12_PATH" -k "$KEYCHAIN" -P "$IOS_P12_PASSWORD" \
  -T /usr/bin/codesign -T /usr/bin/security -f pkcs12 -A

# The line everyone forgets. Without it codesign tries to open a password
# window and you get "User interaction is not allowed".
security set-key-partition-list -S apple-tool:,apple:,codesign: \
  -s -k "$KEYCHAIN_PW" "$KEYCHAIN" >/dev/null

security list-keychains -d user -s "$KEYCHAIN" "$LOGIN_KEYCHAIN"
security find-identity -v -p codesigning "$KEYCHAIN"

if ! security find-identity -v -p codesigning "$KEYCHAIN" | grep -q "Apple Distribution"; then
  echo "No Apple Distribution identity found. Wrong .p12 or wrong password." >&2
  exit 1
fi

# ========================= 2. profile ======================================
step "2/6 downloading the provisioning profile from Apple"
chmod 600 "$P8_PATH"
P8_PATH="$P8_PATH" \
APP_IDENTIFIER="$APP_IDENTIFIER" \
PROFILE_TYPE="$PROFILE_TYPE" \
OUT_DIRS="$(printf '["%s","%s"]' "$PROFILE_DIR_NEW" "$PROFILE_DIR_OLD")" \
ENV_OUT="$WORK/profile.env" \
python3 "$CI_DIR/fetch_profile.py"

# shellcheck disable=SC1090
source "$WORK/profile.env"
INSTALLED_PROFILE="$PROFILE_FILE"

# ========================= 3. flutter ======================================
step "3/6 compiling the Flutter code, unsigned"
$FLUTTER --version
$FLUTTER clean
$FLUTTER pub get
$FLUTTER build ios --release --no-codesign \
  --build-name="$BUILD_NAME" \
  --build-number="$BUILD_NUMBER" \
  ${FLUTTER_FLAVOR:+--flavor "$FLUTTER_FLAVOR"}

# ========================= 4. archive ======================================
step "4/6 archiving with manual signing"
xcodebuild archive \
  -workspace "ios/Runner.xcworkspace" \
  -scheme "$SCHEME" \
  -configuration "$XCODE_CONFIG" \
  -sdk iphoneos \
  -destination 'generic/platform=iOS' \
  -archivePath "$ARCHIVE" \
  -quiet \
  CODE_SIGN_STYLE=Manual \
  DEVELOPMENT_TEAM="$TEAM_ID" \
  CODE_SIGN_IDENTITY="Apple Distribution" \
  PROVISIONING_PROFILE_SPECIFIER="$PROFILE_NAME" \
  OTHER_CODE_SIGN_FLAGS="--keychain $KEYCHAIN"

# ========================= 5. export =======================================
# Flutter's own plist has only method and uploadBitcode. Manual signing needs
# teamID and a provisioningProfiles map, so we write our own.
step "5/6 exporting the ipa"
cat > "$WORK/ExportOptions.plist" <<PLIST
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
  <key>method</key><string>$EXPORT_METHOD</string>
  <key>teamID</key><string>$TEAM_ID</string>
  <key>signingStyle</key><string>manual</string>
  <key>signingCertificate</key><string>Apple Distribution</string>
  <key>uploadSymbols</key><true/>
  <key>stripSwiftSymbols</key><true/>
  <key>destination</key><string>export</string>
  <key>provisioningProfiles</key>
  <dict>
    <key>$APP_IDENTIFIER</key><string>$PROFILE_NAME</string>
  </dict>
</dict>
</plist>
PLIST

xcodebuild -exportArchive \
  -archivePath "$ARCHIVE" \
  -exportPath "$IPA_DIR" \
  -exportOptionsPlist "$WORK/ExportOptions.plist" \
  -allowProvisioningUpdates \
  -authenticationKeyPath "$P8_PATH" \
  -authenticationKeyID "$ASC_KEY_ID" \
  -authenticationKeyIssuerID "$ASC_ISSUER_ID"

IPA_PATH="$(ls "$IPA_DIR"/*.ipa | head -n1)"
echo "ipa ready: $IPA_PATH"
codesign -dv --verbose=4 "$ARCHIVE/Products/Applications/$SCHEME.app" 2>&1 \
  | grep -E "Authority|TeamIdentifier" || true

# ========================= 6. upload =======================================
if [ "$DO_UPLOAD" = "true" ]; then
  step "6/6 uploading to App Store Connect"
  mkdir -p "$HOME/.appstoreconnect/private_keys"
  cp "$P8_PATH" "$HOME/.appstoreconnect/private_keys/AuthKey_$ASC_KEY_ID.p8"
  xcrun altool --validate-app -f "$IPA_PATH" -t ios \
    --apiKey "$ASC_KEY_ID" --apiIssuer "$ASC_ISSUER_ID"
  xcrun altool --upload-app -f "$IPA_PATH" -t ios \
    --apiKey "$ASC_KEY_ID" --apiIssuer "$ASC_ISSUER_ID"
  echo "uploaded. Watch the Activity tab in App Store Connect."
else
  step "6/6 upload skipped, DO_UPLOAD is false"
fi

step "done: $BUILD_NAME ($BUILD_NUMBER)"

Section 06

The build commands

Every command the pipeline fires, and the same commands to run by hand when you want to watch what is happening.

First: find your scheme and flavor

If the project has flavors, the scheme is usually not Runner. Check before you fill in pipeline.properties.

Terminal · in the Flutter app folder
xcodebuild -list -workspace ios/Runner.xcworkspace

It prints the schemes and the build configurations. A project with a prod flavor usually has scheme prod and configuration Release-prod. Whatever it prints is what goes in the settings file.

Flutter, with the pinned SDK

The pipeline pins Flutter with FVM, so always say fvm flutter, never plain flutter. Plain flutter uses whatever SDK happens to be on the machine and your build quietly stops matching the pipeline.

Setting up the SDK
fvm install 3.44.6 --setup      # download that exact version
fvm use 3.44.6 --force          # pin this folder to it
fvm flutter --version           # confirm

iOS — the five commands, in order

iOS build
# 1. clean and get packages
fvm flutter clean
fvm flutter pub get

# 2. compile, unsigned. Xcode signs it later, not Flutter.
fvm flutter build ios --release --no-codesign \
  --build-name=1.0.0 \
  --build-number=32 \
  --flavor prod

# 3. archive, signing by hand with the downloaded profile
xcodebuild archive \
  -workspace ios/Runner.xcworkspace \
  -scheme prod \
  -configuration Release-prod \
  -sdk iphoneos \
  -destination 'generic/platform=iOS' \
  -archivePath build/ci/prod.xcarchive \
  CODE_SIGN_STYLE=Manual \
  DEVELOPMENT_TEAM=ABCDE12345 \
  CODE_SIGN_IDENTITY="Apple Distribution" \
  PROVISIONING_PROFILE_SPECIFIER="CM App AppStore"

# 4. export the .ipa
xcodebuild -exportArchive \
  -archivePath build/ci/prod.xcarchive \
  -exportPath build/ci/ipa \
  -exportOptionsPlist build/ci/ExportOptions.plist

# 5. upload to TestFlight
xcrun altool --upload-app -f build/ci/ipa/*.ipa -t ios \
  --apiKey 2X9R4HXF34 \
  --apiIssuer 69a6de7e-1234-4c5b-8f21-9a0bcdef1234

Do not run pod install yourselfflutter build ios runs pod install for you. Running it again by hand only adds a minute to every build.

Android

Android build
# Play Store upload file
fvm flutter build appbundle --release \
  --build-name=1.0.0 --build-number=32 --flavor prod

# a plain apk, for testers who install by hand
fvm flutter build apk --release \
  --build-name=1.0.0 --build-number=32 --flavor prod

# where the files land:
#   build/app/outputs/bundle/prodRelease/app-prod-release.aab
#   build/app/outputs/flutter-apk/app-prod-release.apk

Android signing needs android/key.properties and android/cm-app.jks. The pipeline already downloads both from storage before this step runs.

Shorebird — code push

The job has a BUILD_RUNNER choice. Shorebird runs its own build, so it replaces the Flutter commands rather than adding to them.

Shorebird
# a release: a full build that users install from the store
shorebird release ios --flavor prod -- --build-name=1.0.0 --build-number=32
shorebird release android --flavor prod -- --build-name=1.0.0 --build-number=32

# a patch: the code push, no store review
shorebird patch ios --release-version 1.0.0+32 --flavor prod
shorebird patch android --release-version 1.0.0+32 --flavor prod

Shorebird reads its token from SHOREBIRD_TOKEN in the environment, which comes from the Jenkins credential named in pipeline.properties. The signing setup in this runbook still applies to shorebird release ios — it archives with Xcode underneath.

Prove the certificate

Section 08

When it breaks

Almost every failure is one of these ten. The message on the left, the real cause on the right.

What you seeWhat it means, and what to do
User interaction is not allowed The set-key-partition-list line did not run, or the keychain password did not match. macOS wants to show a password window and nobody is there to click it.
errSecInternalComponent Same cause, different words. Check the partition list line, and that the keychain is unlocked.
No signing certificate "iOS Distribution" found The certificate went into one keychain and xcodebuild looked in another. Run security find-identity -v -p codesigning to see what is actually visible.
no ACTIVE profile found for <bundle id> The profile does not exist, or its type is different. Create it once in the portal, and check IOS_PROFILE_TYPE matches what you made.
exportArchive failed, no useful message Nearly always an incomplete ExportOptions.plist. On Xcode 15 or older use IOS_EXPORT_METHOD=app-store instead of app-store-connect.
Works over SSH, fails from Jenkins The agent is a LaunchDaemon with no user session, or its PATH is missing /opt/homebrew/bin. Fix the plist, then launchctl unload and load -w again.
The build number has already been used Every upload needs a fresh build number. Raise APP_BUILD_NUMBER. A used number can never be reused.
The job never starts, and prints nothing No online node carries the label macos. Check Manage Jenkins → Nodes.
Flutter version mismatch The pipeline compares the SDK version exactly. Either change FLUTTER_VERSION, or let FVM install the one written there.
pod: command not found CocoaPods is missing on the Pipeline Mac, or brew is not in the agent's PATH. brew install cocoapods.

If the app has extensions

Widgets, push notification services and share extensions each need their own provisioning profile. Add a second entry to the provisioningProfiles map in the plist and set the specifier per target — the plain PROVISIONING_PROFILE_SPECIFIER applies to every target and will pick the wrong one.

The one thing that comes back every year

The distribution certificate expires after twelve months. When it does:

  • Export a fresh dist.p12 on the Development Mac
  • Upload it over the old one in the bucket
  • Update ios-p12-password in Jenkins if you chose a new password

Nothing else changes. The API key does not expire, and the profile is downloaded fresh every build.

Two things to never do

Never log into Xcode on the Pipeline Mac. It creates its own certificates and quietly competes with the pipeline's.
Never create a new distribution certificate to fix a problem. There are only two or three for the whole company. Find the old one first.
Tooling: only what ships with macOS and Xcode — security, xcodebuild, xcrun, python3, openssl — plus FVM, CocoaPods and the AWS CLI, which the pipeline installs with Homebrew. No fastlane, no gems, no third-party signing tool.
